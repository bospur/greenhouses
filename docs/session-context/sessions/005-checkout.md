# Сессия 005 — A5 оформление заказа

- Дата: 2026-11-16
- Цель: `/checkout` (черновик, доставка по ТК, контакты, оплата) и `/order/:id` (статус, оплата по QR) на моках.

## Результат

- `/checkout?product=slug` и `/checkout?<config>` кладут товар в `orderDraft` (Zustand + persist) и заменяют адрес
  на чистый `/checkout`; черновик переживает перезагрузку. Пустой черновик — «Вы ещё не выбрали теплицу»,
  модель пропала из каталога — отдельное пояснение.
- Страница: индикатор шагов (Теплица ✓ → Доставка → Контакты → Оплата), три нумерованные секции слева,
  справа «липкая» сводка: карточка товара (мини-чертёж, параметры, «Изменить» / «Изменить размеры») и итог
  с кнопкой «Оформить и оплатить». На ≤960 px: карточка товара сверху, итог — после шагов.
- Доставка: комбобокс города (debounce 250 мс, стрелки/Enter/Esc, ARIA combobox), котировки ТК
  (СДЭК дверь/терминал, Деловые Линии дверь/терминал, ПЭК терминал, самовывоз до 120 км от склада),
  адрес — только для доставки до двери. Груз (вес/объём) оценивается на фронте.
- Контакты: имя, телефон с маской `+7 (999) 123-45-67` (ввод с 8/7/+7 и вставка), email и комментарий — необязательно.
- Оплата: СБП (QR) или карта (ЮKassa redirect). Отправка: `POST /orders` → `POST /orders/:id/payment` →
  `/order/:id?pay=1` (окно оплаты открыто), черновик очищается.
- `/order/:id`: статус-бейдж, таймлайн (оформлен → оплачен → передан в ТК → доставлен), блок «Ждёт оплаты» /
  «Оплата получена», карточки товара, доставки, получателя и суммы. Пока платёж `pending` — опрос раз в 3 с;
  мок подтверждает оплату через ~10 с, окно переключается на «Оплата прошла». Неизвестный заказ — «Заказ не найден».
- Конфигуратор понимает `?shape=…&w=…` (ссылка «Изменить» из оформления возвращает ту же конфигурацию).
- Проверено в браузере: 1024 и 390, весь путь модель → заказ → оплата; lint / typecheck / build — зелёные.

## Решения по ходу

- Data layer: `deliverySource` (`GET /delivery/cities?q=`, `POST /delivery/quotes`), `orderSource`
  (`POST /orders`, `GET /orders/:id`, `POST /orders/:id/payment`) → `DeliveryRepository`, `OrderRepository` → RQ-хуки.
  Моки: города с расстоянием от склада (Подольск), тарифы ТК по весу/объёму/расстоянию; заказы — в localStorage.
- Мок принимает заказ только по последней выданной котировке (как будет на сервере); иначе ошибка
  «Стоимость доставки устарела». Цена своей теплицы приходит в `clientPreview` — сервер пересчитает (ADR-001).
- Заказ ссылается на котировку по `quoteId` (стабилен для «город + тариф»); тариф (`deliveryService`) хранится в форме
  рядом — от него зависит обязательность адреса (`superRefine`).
- Форма — одна RHF + Zod (`checkoutSchema`), шаги не прячутся; «пройденность» шага — по ошибкам `safeParse`.
  Ошибки показываются по уходу с поля, после первой отправки — сразу.
- Созданный заказ и платёж кладутся в кеш RQ (`setQueryData`), store их не хранит.
- Новое в shared: `FormField` / `Input` / `TextArea`, `Modal` (нативный `<dialog>`), `useDebouncedValue`
  (`shared/hooks`), `formatDateTime` / `formatTime`, иконки `qr`, `clock`, `user`, `search`, `alert`, `cart`;
  `APP_ROUTES.configurator.withConfig`, `APP_ROUTES.order.pay`, `COMPANY.warehouseAddress`.
- Cross-module импорты `checkout → configurator/catalog` — ADR-004.
- QR в моке — псевдо-узор (не сканируется); настоящий код — из ответа ЮKassa в C1.
